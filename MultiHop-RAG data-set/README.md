验证思路：

**目标：让 MiniCPM 先查资料，再结合多篇文章回答问题，并验证哪些改进真正有效。**

## 1. 准备知识库

把 `corpus.json` 中的 609 篇文章切成小片段，方便查找和交给模型阅读。

## 2. 跑基础 RAG（当前阶段）

用 BM25 根据关键词找相关片段，再把“问题 + 片段”交给未微调的 MiniCPM 回答。

跑完全部 2,556 道题，得到初始成绩，作为后续比较的参照。这一步不训练模型。

## 3. 看模型为什么答错

检查错误题目：是没有找到资料、资料找得不全，还是资料齐全但模型理解错了。

目的：知道该改检索，还是该改模型回答。

## 4. 改进检索

根据错误情况，尝试加入语义检索，或把最有用的片段重新排序、放到前面。

每次改动后重新测试，与基础 RAG 比较，看准确率是否提高。

## 5. 尝试微调（可选）

如果资料找对了，但模型仍经常答错，再用检查过的“资料 + 问题 + 正确答案”训练 MiniCPM。

固定检索条件，比较微调前后的成绩，判断训练有没有帮助。训练题与评测题要区分清楚。

## 6. 汇总结果

比较各组实验的准确率、耗时和显存占用，分析成功与失败案例。

最后用老师的固定官方评分脚本复核，整理预测文件、运行日志、代码和报告。

## 计划对照的实验

| 实验 | 做什么 |
| --- | --- |
| A：基础 RAG | BM25 检索 + 原始 MiniCPM |
| B：改进检索 | 加入语义检索，比较找资料的效果 |
| C：改进排序 | 在 B 上重新筛选、排序证据片段 |
| D：微调，可选 | 固定检索方案，比较微调前后的模型 |

**当前进度：前 10 题已跑通，完整 2,556 题的结果尚待确认。下一步先看全量成绩和错误原因。**
