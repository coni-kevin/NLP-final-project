Natural Language Processing
大作业官方评测教程

本教程帮助各组在提交前，用固定版本的 MultiHop-RAG 官方脚本评测自己的预测，并把实验结果写进报告。自测只需普通 CPU 和 Python，不需要 GPU，也不会调用生成模型。

学生提交报告 Word、同内容 PDF、predictions.json 和 execution record。自测输出留在本地，结果写入报告，无需另交 scores 文件。教师会根据最终预测统一复核。全部材料及 GitHub 代码须在 2026 年 11 月 1 日前准备并提交，报告附可访问的仓库地址。

1　准备工作目录

安装 Python 3.10 或更新版本。解压教程包，在解压目录中打开终端，将自己生成的 predictions.json 复制到该目录。不要把空白预测模板当作实验结果。

eval_tutorial/
  学生自测教程.html
  download_eval_files.py
  prepare_eval.py
  predictions.json           ← 放入本组实际生成的预测

以下命令适用于 Windows PowerShell、macOS 和 Linux。Windows 若不识别 python，可将命令中的 python 换成 py；macOS/Linux 可换成 python3。所有步骤使用同一 Python 环境。

python --version
python -m pip install tqdm
python download_eval_files.py

下载工具会获取官方 qa_evaluate.py 和 MultiHopRAG.json，校验 SHA-256 后保存。它不修改官方代码。这里不需要下载 corpus.json：生成答案时才需要检索文档库。

2　检查预测文件

predictions.json 是 UTF-8 JSON 数组，包含全部 2,556 个题号。每条记录只保留下列两个字段；示例仅展示两条记录，并非完整文件：

[
  {"question_id": "q0000", "model_answer": "本组模型生成的最终短答案"},
  {"question_id": "q0001", "model_answer": "本组模型生成的最终短答案"}
]
  • q0000 对应原始 MultiHopRAG.json 的第一题，依次到 q2555。不能先打乱官方问题顺序再编号。
  • model_answer 仅保存实际最终短答案，通常为英文。无法由证据回答时输出 Insufficient Information。
  • 程序失败或漏答时保留该题，答案写空字符串 ""，执行记录中说明原因。不要删除失败题以提高得分。
  • 不要放入标准答案、参考证据标注、推理过程或候选答案列表。标准答案只能用于评测与分析。

3　转换为官方脚本的输入格式

课程提交文件使用 question_id；官方脚本需要问题原文 query，并使用 question_type 分组。直接把课程 JSON 交给官方脚本会出现字段错误。先运行：

python prepare_eval.py --predictions predictions.json --queries MultiHopRAG.json --output qa_submission.json

正常输出会显示 Validated 2556 questions 和空答案数量。转换工具检查完整题号、重复项、字段类型和数据文件版本，并生成：

[
  {
    "query": "从官方问题文件读取的原始问题",
    "question_type": "从官方文件读取的题型",
    "model_answer": "本组模型生成的最终短答案"
  }
]

该工具只校验和转换格式，不计算分数，不把标准答案写入预测。qa_submission.json 是本地评测中间文件；最终提交的预测文件仍为 predictions.json。

4　运行官方评测

python qa_evaluate.py --file qa_submission.json --queries MultiHopRAG.json

脚本依次打印各题型结果和 Overall Metrics。如需在本地保留输出，可使用：

python qa_evaluate.py --file qa_submission.json --queries MultiHopRAG.json > eval_output.txt

进度条可能仍显示在终端，这是正常现象。结果写入当前目录的 eval_output.txt。每次重新生成 predictions.json 后，必须重新执行第 3、4 步，避免评测旧文件。

5　读取结果并写入报告

找到最后的 Overall Metrics，使用其中的 Accuracy。例如输出为 0.7469，则报告中写约 74.69%，benchmark 分数 B 约为 74.69。这是示例，不是本组成绩。

四类问题的数量应分别为：推断 inference_query 816 题、比较 comparison_query 856 题、时间 temporal_query 583 题、无答案 null_query 301 题，总计 2,556 题。请在报告 Evaluation Result 节填写下表，并说明模型、RAG 方法和实际运行配置。

using the official qa_evaluate.py script at commit
c1c1287aa60a94acf9c4d20c891c9cd611a0f6e8.
Our overall official Accuracy was [XX.XX]%, corresponding to a
benchmark score B of approximately [XX.XX]. Failed predictions were
kept as empty answers. Per-type results are reported in the table.

Benchmark 得分只用于 Response Accuracy 单项，该项占总成绩 40%。B ≥ 75 对应单项 90–100 分档，70 ≤ B < 75 对应 80–89 分档，65 ≤ B < 70 对应 60–79 分档；具体单项分数由教师评定。其余评分项另行评阅。

不要用四舍五入后的显示值跨档。官方终端仅打印四位小数，报告可保留两位百分数；最终档位按教师复核的未舍入比例确定。

6　理解官方指标

此固定版本将预测与参考答案转为小写、按空白切词，只要存在重合词就判为该题匹配成功。它不是严格 Exact Match，也不是语义裁判评分；该版本输出的 Precision、Recall、F1 和 Accuracy 数值相同。报告请明确写“official-script Accuracy”，不要将四个相同值解释成四项独立能力。

按任务书只评最终短答案。不要把检索全文或多种候选答案拼进 model_answer 来增加词重合；这些内容放入 execution record。评测规则以固定官方脚本原样执行。

7　常见问题

现象处理
No module named tqdm用运行评测的同一 Python 执行 python -m pip install tqdm。
找不到文件在教程目录运行命令，或给参数传完整路径；带空格的路径加双引号。
下载超时或网络失败恢复 GitHub / Hugging Face 访问后重试；已校验成功的文件会直接复用。不要改用未知版本。
文件校验失败把当前文件移到其他位置备份，再重新下载固定版本；不要编辑或重新排序官方问题文件。
Missing / Duplicate / Unknown question ID修复题号。缺失或失败题也要保留记录，model_answer 写空字符串；正式评测要求全部题目。
KeyError: query 或题型 unknown重新执行格式转换，并将 qa_submission.json 传给官方脚本。
Skipping query without a gold answer本教程的完整转换流程不应出现此消息。检查是否使用了转换产物及固定数据文件，不要把跳过题目的分数当作全量结果。
分数为 0 或偏低先检查是否误用了空模板、题号是否与官方原始顺序一致，再检查模型最终答案和实际检索过程。

8　提交前确认

报告写入本次最终预测的自测成绩和分析，并导出同内容 PDF；提交完整 predictions.json 和相应 execution record；GitHub 仓库与这些结果对应。不用单独交 eval_output.txt、qa_submission.json 或 scores 文件夹。正式成绩以教师复核为准。
